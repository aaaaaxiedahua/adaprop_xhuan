## 1. 背景与动机

### 1.1 AdaProp 的当前局限

AdaProp 通过可微采样学习自适应传播路径，但存在以下问题：

```python
# transductive/models.py:86-95 (当前采样机制)
diff_node_logit = self.W_samp(hidden_new[bool_diff_node_idx]).squeeze(-1)
node_scores = torch.ones((batchsize, self.n_ent)).cuda() * float('-inf')
node_scores[diff_node[:,0], diff_node[:,1]] = diff_node_logit
node_scores = self.softmax(node_scores)  # 仅基于神经网络学习
```

**问题分析**：
- ❌ **缺乏结构化先验**：采样分布 `W_samp` 是简单的线性变换，无法显式利用知识图谱的逻辑模式
- ❌ **端到端学习效率低**：需要大量训练数据才能隐式学习到常见的推理规则
- ❌ **可解释性差**：无法解释为什么某些节点被采样

### 1.2 逻辑规则的优势

知识图谱中存在大量可挖掘的逻辑规则（Logic Rules），例如：

```
规则示例（FB15k-237）：
IF Person(X) -[born_in]-> City(Y) AND City(Y) -[located_in]-> Country(Z)
THEN Person(X) -[nationality]-> Country(Z)

符号表示（Horn 子句）：
born_in(X,Y) ∧ located_in(Y,Z) => nationality(X,Z)

路径模式：
r1(X,Y) ∧ r2(Y,Z) => r3(X,Z)  [2-hop规则]
```

**引入规则的收益**：
- ✅ **加速收敛**：显式规则减少学习空间
- ✅ **提升泛化**：规则在低频关系上提供先验指导
- ✅ **增强可解释性**：采样决策可追溯到逻辑规则

## 2. 逻辑规则基础

### 2.1 Horn 子句（Horn Clause）

Horn 子句是知识图谱推理中最常用的规则形式：

```
通用形式：
B1 ∧ B2 ∧ ... ∧ Bn => H

其中：
- B1, B2, ..., Bn 是规则体（Body），称为前件（Antecedent）
- H 是规则头（Head），称为后件（Consequent）
- ∧ 表示逻辑与（AND）
```

**示例**：
```
1-hop 规则（对称性）：
married(X,Y) => married(Y,X)

2-hop 规则（传递性）：
parent(X,Y) ∧ parent(Y,Z) => grandparent(X,Z)

3-hop 规则（复合推理）：
born_in(X,Y) ∧ located_in(Y,Z) ∧ is_capital(Z,W) => nationality(X,W)
```

### 2.2 规则质量度量

挖掘的规则需要量化其质量，常用指标：

**1. 支持度（Support）**
```python
support(r) = count(r)  # 规则在KG中被触发的次数

示例：
规则: parent(X,Y) ∧ parent(Y,Z) => grandparent(X,Z)
支持度 = 1523  # KG中有1523个三元组符合此规则
```

**2. 置信度（Confidence）**
```python
confidence(r) = support(r) / count(body(r))

示例：
count(parent(X,Y) ∧ parent(Y,Z)) = 2000  # 路径总数
support(grandparent 规则) = 1523
confidence = 1523 / 2000 = 0.76  # 76%的祖孙路径确实存在grandparent关系
```

**3. PCA 置信度（Partial Completeness Assumption）**
```python
pca_confidence(r) = support(r) / (count(body(r)) + count(head(r)))

# 考虑了头部关系的稀疏性，对低频关系更友好
```

**规则筛选标准**：
```python
# 典型阈值
min_support = 10          # 至少出现10次
min_confidence = 0.1      # 置信度至少10%
max_length = 3            # 最多3-hop规则（控制复杂度）
```

### 2.3 规则挖掘算法

#### AMIE+ 算法（推荐）

AMIE+（Association Rule Mining under Incomplete Evidence）是最常用的KG规则挖掘算法：

**核心思想**：
1. 从单关系规则开始：`r(X,Y) => r'(X,Y)`
2. 逐步添加原子（atom）扩展规则体
3. 使用剪枝策略避免组合爆炸

**伪代码**：
```python
def amie_plus(KG, min_support, min_confidence):
    rules = []

    # 初始化：单关系规则
    for r in relations:
        rules.append(Rule(body=[], head=r))

    # 迭代扩展
    while rules:
        new_rules = []
        for rule in rules:
            # 尝试添加新原子
            for r in relations:
                for var_binding in possible_bindings(rule, r):
                    extended_rule = extend(rule, r, var_binding)

                    # 计算支持度和置信度
                    sup = compute_support(extended_rule, KG)
                    conf = compute_confidence(extended_rule, KG)

                    # 剪枝
                    if sup >= min_support and conf >= min_confidence:
                        new_rules.append(extended_rule)
                        yield extended_rule

        rules = new_rules
```

**优势**：
- ✅ 完备性高：能挖掘任意长度的规则
- ✅ 效率高：智能剪枝减少搜索空间
- ✅ 开源实现：https://github.com/lajus/amie

#### RuleN 算法（备选）

RuleN 使用神经网络学习规则嵌入：

```python
# 规则嵌入向量
rule_emb = f(body_relations, head_relation)

# 通过嵌入相似度筛选高质量规则
score(rule) = cosine_similarity(rule_emb, target_emb)
```

**适用场景**：
- 数据量大时（AMIE+在大图上较慢）
- 需要端到端学习时

## 3. 核心设计思想

### 3.1 规则引导采样的直觉

**传统 AdaProp 采样**：
```python
# 仅基于节点的神经表示打分
score(node) = W_samp(h_node)
```

**规则引导采样**：
```python
# 神经分数 + 规则分数
score(node) = W_samp(h_node) + λ * rule_score(node, query_relation)

# 规则分数衡量：当前路径触发了多少条与查询关系相关的规则
```

**示例说明**：

假设查询：`(Alice, nationality, ?)`

当前第2层采样，候选节点包括：
- `Beijing` (通过路径: Alice -[born_in]-> Beijing)
- `Restaurant_1` (通过路径: Alice -[eat_at]-> Restaurant_1)

已知规则：
```
R1: born_in(X,Y) ∧ located_in(Y,Z) => nationality(X,Z)  [confidence=0.8]
R2: born_in(X,Y) => nationality(X,Y)  [confidence=0.3]
```

**评分计算**：

对于 `Beijing`：
- 神经分数：`W_samp(h_Beijing) = 0.6`
- 规则分数：
  - 路径 `Alice -[born_in]-> Beijing` 可能触发 R1 (如果继续传播)
  - rule_score = 0.8 (R1的置信度)
- **总分 = 0.6 + 0.5 * 0.8 = 1.0**

对于 `Restaurant_1`：
- 神经分数：`W_samp(h_Restaurant_1) = 0.7`
- 规则分数：无相关规则触发
  - rule_score = 0.0
- **总分 = 0.7 + 0.5 * 0.0 = 0.7**

**结果**：`Beijing` 被优先采样（符合常识：出生地与国籍相关）

### 3.2 规则匹配的关键问题

**问题1：如何判断当前路径触发了某条规则？**

**解决方案**：路径模式匹配

```python
def path_matches_rule(current_path, rule):
    """
    检查当前路径是否匹配规则的前件

    Args:
        current_path: [(q_node, r1, n1), (n1, r2, n2), ...]
        rule: Rule(body=[(r1, r2)], head=r3, confidence=0.8)

    Returns:
        bool: 是否匹配
    """
    if len(current_path) != len(rule.body):
        return False

    for i, (h, r, t) in enumerate(current_path):
        if r != rule.body[i]:
            return False

    return True
```

**问题2：在线路径匹配太慢怎么办？**

**解决方案**：索引优化（见后文 [7.2 规则索引优化](#72-规则索引优化)）

### 4.2 数据结构设计

#### 规则表示

```python
from dataclasses import dataclass
from typing import List, Tuple

@dataclass
class Rule:
    """
    表示一条Horn规则

    Example:
        Rule(
            body=[(1, 2)],  # 关系ID: r1, r2
            head=5,         # 关系ID: r5
            confidence=0.82,
            support=1523
        )
        表示: r1(X,Y) ∧ r2(Y,Z) => r5(X,Z)
    """
    body: List[int]          # 规则体的关系序列 [r1, r2, ...]
    head: int                # 规则头的关系 r_head
    confidence: float        # 置信度
    support: int             # 支持度
    length: int              # 规则长度（hop数）

    def __hash__(self):
        return hash((tuple(self.body), self.head))

    def __repr__(self):
        body_str = " ∧ ".join([f"r{r}" for r in self.body])
        return f"{body_str} => r{self.head} (conf={self.confidence:.2f})"
```

#### 规则索引

```python
from collections import defaultdict

class RuleIndex:
    """
    规则索引：快速查找与某个查询关系相关的规则
    """
    def __init__(self, rules: List[Rule]):
        # head_relation -> List[Rule]
        self.head_to_rules = defaultdict(list)

        # (body_prefix, head_relation) -> List[Rule]
        # 用于快速路径匹配
        self.path_to_rules = defaultdict(list)

        for rule in rules:
            self.head_to_rules[rule.head].append(rule)

            # 为每个前缀长度建立索引
            for prefix_len in range(1, len(rule.body) + 1):
                prefix = tuple(rule.body[:prefix_len])
                self.path_to_rules[(prefix, rule.head)].append(rule)

    def get_rules_by_head(self, head_relation: int) -> List[Rule]:
        """获取所有头部为指定关系的规则"""
        return self.head_to_rules.get(head_relation, [])

    def get_rules_by_path(self, path_relations: List[int],
                          head_relation: int) -> List[Rule]:
        """获取匹配指定路径前缀的规则"""
        prefix = tuple(path_relations)
        return self.path_to_rules.get((prefix, head_relation), [])
```

## 5. 代码详解

### 5.1 规则挖掘模块

创建新文件：`transductive/rule_mining.py`

```python
import numpy as np
from collections import defaultdict, Counter
from typing import List, Tuple, Set
from dataclasses import dataclass
import pickle
import os

@dataclass
class Rule:
    body: List[int]
    head: int
    confidence: float
    support: int
    length: int

    def __hash__(self):
        return hash((tuple(self.body), self.head))

class SimplifiedAMIE:
    """
    简化版 AMIE+ 规则挖掘算法

    仅挖掘 2-hop 和 3-hop 路径规则（平衡效果与效率）
    """
    def __init__(self, min_support=10, min_confidence=0.1, max_length=3):
        self.min_support = min_support
        self.min_confidence = min_confidence
        self.max_length = max_length

    def mine_rules(self, train_triples: np.ndarray, n_rel: int) -> List[Rule]:
        """
        从训练三元组中挖掘规则

        Args:
            train_triples: [N, 3] 数组，每行 (head, relation, tail)
            n_rel: 关系总数

        Returns:
            List[Rule]: 挖掘到的规则列表
        """
        print("[Rule Mining] 开始挖掘规则...")

        # 构建知识图谱索引
        print("[Rule Mining] 构建KG索引...")
        kg_index = self._build_kg_index(train_triples)

        # 统计路径
        print("[Rule Mining] 统计路径模式...")
        path_counts = self._count_paths(train_triples, kg_index)

        # 生成规则
        print("[Rule Mining] 生成规则...")
        rules = self._generate_rules(path_counts, train_triples)

        print(f"[Rule Mining] 完成！共挖掘到 {len(rules)} 条规则")
        return rules

    def _build_kg_index(self, triples: np.ndarray) -> dict:
        """
        构建 KG 索引：head -> [(relation, tail), ...]
        """
        kg = defaultdict(list)
        for h, r, t in triples:
            kg[h].append((r, t))
        return kg

    def _count_paths(self, triples: np.ndarray, kg_index: dict) -> dict:
        """
        统计所有 2-hop 和 3-hop 路径

        Returns:
            path_counts: {
                (r1, r2): {r3: count},  # 2-hop
                (r1, r2, r3): {r4: count},  # 3-hop
            }
        """
        path_counts = defaultdict(lambda: defaultdict(int))

        # 2-hop 路径
        print("  统计 2-hop 路径...")
        for h, r1, t1 in triples:
            if h not in kg_index:
                continue
            for r2, t2 in kg_index.get(t1, []):
                # 路径: h -[r1]-> t1 -[r2]-> t2
                # 检查是否存在直接边 h -[r3]-> t2
                for r3, t3 in kg_index.get(h, []):
                    if t3 == t2:
                        path_counts[(r1, r2)][r3] += 1

        # 3-hop 路径（可选，计算量较大）
        if self.max_length >= 3:
            print("  统计 3-hop 路径...")
            # 限制样本数量避免过慢
            sampled_triples = triples[np.random.choice(
                len(triples),
                min(len(triples), 10000),
                replace=False
            )]

            for h, r1, t1 in sampled_triples:
                for r2, t2 in kg_index.get(t1, []):
                    for r3, t3 in kg_index.get(t2, []):
                        # 路径: h -[r1]-> t1 -[r2]-> t2 -[r3]-> t3
                        for r4, t4 in kg_index.get(h, []):
                            if t4 == t3:
                                path_counts[(r1, r2, r3)][r4] += 1

        return path_counts

    def _generate_rules(self, path_counts: dict,
                        triples: np.ndarray) -> List[Rule]:
        """
        从路径统计生成规则
        """
        rules = []

        # 统计每个关系的出现次数（用于计算置信度）
        relation_counts = Counter(triples[:, 1])

        for body, head_counts in path_counts.items():
            # 计算body的总数
            body_count = sum(head_counts.values())

            for head, support in head_counts.items():
                # 过滤低支持度
                if support < self.min_support:
                    continue

                # 计算置信度
                confidence = support / body_count if body_count > 0 else 0

                # 过滤低置信度
                if confidence < self.min_confidence:
                    continue

                # 创建规则
                rule = Rule(
                    body=list(body),
                    head=head,
                    confidence=confidence,
                    support=support,
                    length=len(body)
                )
                rules.append(rule)

        # 按置信度排序
        rules.sort(key=lambda r: r.confidence, reverse=True)

        return rules

    def save_rules(self, rules: List[Rule], save_path: str):
        """保存规则到文件"""
        with open(save_path, 'wb') as f:
            pickle.dump(rules, f)
        print(f"[Rule Mining] 规则已保存至 {save_path}")

    def load_rules(self, load_path: str) -> List[Rule]:
        """从文件加载规则"""
        with open(load_path, 'rb') as f:
            rules = pickle.load(f)
        print(f"[Rule Mining] 从 {load_path} 加载了 {len(rules)} 条规则")
        return rules


def mine_and_save_rules(data_path: str, min_support=10, min_confidence=0.1):
    """
    便捷函数：挖掘并保存规则

    Usage:
        from rule_mining import mine_and_save_rules
        mine_and_save_rules('./data/fb15k-237/', min_support=20, min_confidence=0.15)
    """
    # 加载训练数据
    train_file = os.path.join(data_path, 'train.txt')
    train_triples = []
    with open(train_file, 'r') as f:
        for line in f:
            h, r, t = line.strip().split('\t')
            train_triples.append([int(h), int(r), int(t)])
    train_triples = np.array(train_triples)

    # 获取关系数
    n_rel = train_triples[:, 1].max() + 1

    # 挖掘规则
    miner = SimplifiedAMIE(min_support=min_support, min_confidence=min_confidence)
    rules = miner.mine_rules(train_triples, n_rel)

    # 保存
    save_path = os.path.join(data_path, 'rules.pkl')
    miner.save_rules(rules, save_path)

    # 打印统计
    print("\n规则统计：")
    print(f"  总数: {len(rules)}")
    print(f"  2-hop: {sum(1 for r in rules if r.length == 2)}")
    print(f"  3-hop: {sum(1 for r in rules if r.length == 3)}")
    print(f"  平均置信度: {np.mean([r.confidence for r in rules]):.3f}")
    print(f"  平均支持度: {np.mean([r.support for r in rules]):.1f}")

    # 打印top-10规则
    print("\nTop-10 规则（按置信度）：")
    for i, rule in enumerate(rules[:10]):
        print(f"  {i+1}. {rule}")

    return rules


# 测试代码
if __name__ == "__main__":
    # 示例：挖掘 Family 数据集的规则
    rules = mine_and_save_rules(
        data_path='./data/family/',
        min_support=5,
        min_confidence=0.1
    )
```

### 5.2 规则评分模块

创建新文件：`transductive/rule_scorer.py`

```python
import torch
import torch.nn as nn
import numpy as np
from collections import defaultdict
from typing import List, Tuple
from rule_mining import Rule, RuleIndex

class RuleScorer(nn.Module):
    """
    规则评分器：为采样节点计算规则分数
    """
    def __init__(self, rules: List[Rule], n_rel: int, device='cuda'):
        super().__init__()
        self.rules = rules
        self.n_rel = n_rel
        self.device = device

        # 构建规则索引
        print("[RuleScorer] 构建规则索引...")
        self.rule_index = self._build_rule_index()

        # 可学习的规则权重（初始化为置信度）
        self.rule_weights = nn.Parameter(
            torch.tensor([r.confidence for r in rules], dtype=torch.float32)
        )

        print(f"[RuleScorer] 初始化完成，共 {len(rules)} 条规则")

    def _build_rule_index(self) -> dict:
        """
        构建规则索引

        Returns:
            {
                head_relation: {
                    1: [Rule],  # 1-hop 规则
                    2: [Rule],  # 2-hop 规则
                    3: [Rule],  # 3-hop 规则
                }
            }
        """
        index = defaultdict(lambda: defaultdict(list))

        for rule in self.rules:
            index[rule.head][rule.length].append(rule)

        return index

    def score_nodes(self,
                    nodes: torch.Tensor,          # [N, 2] (batch_idx, node_id)
                    edges: torch.Tensor,          # [M, 6] (batch_idx, h, r, t, h_idx, t_idx)
                    query_rel: torch.Tensor,      # [batch_size]
                    current_layer: int,           # 当前层数（0-indexed）
                    batch_size: int) -> torch.Tensor:  # 规则分数 [N]
        """
        为候选节点计算规则分数

        核心思想：
        1. 根据当前层数和查询关系，找到相关规则
        2. 追踪从查询节点到当前节点的路径
        3. 检查路径是否匹配规则前件
        4. 累加匹配规则的权重

        Args:
            nodes: 候选节点 [N, 2]，格式 (batch_idx, entity_id)
            edges: 当前层的边 [M, 6]
            query_rel: 查询关系 [batch_size]
            current_layer: 当前GNN层索引
            batch_size: batch大小

        Returns:
            rule_scores: [N]，每个节点的规则分数
        """
        N = nodes.size(0)
        rule_scores = torch.zeros(N, device=self.device)

        # 如果是第0层，没有路径，返回0
        if current_layer == 0:
            return rule_scores

        # 为每个batch构建路径
        for b_idx in range(batch_size):
            q_rel = query_rel[b_idx].item()

            # 获取该查询关系相关的规则（长度 = current_layer）
            relevant_rules = self.rule_index[q_rel].get(current_layer, [])

            if not relevant_rules:
                continue

            # 获取该batch的节点和边
            batch_nodes_mask = (nodes[:, 0] == b_idx)
            batch_edges_mask = (edges[:, 0] == b_idx)

            batch_nodes_idx = torch.where(batch_nodes_mask)[0]
            batch_edges = edges[batch_edges_mask]  # [M', 6]

            # 为每个节点构建路径并匹配规则
            for node_idx in batch_nodes_idx:
                node_id = nodes[node_idx, 1].item()

                # 回溯路径
                path = self._trace_path(node_id, batch_edges, current_layer)

                if path is None:
                    continue

                # 匹配规则
                score = self._match_rules(path, relevant_rules)
                rule_scores[node_idx] = score

        return rule_scores

    def _trace_path(self, target_node: int, edges: torch.Tensor,
                    max_depth: int) -> List[int]:
        """
        从目标节点回溯到查询节点的路径（关系序列）

        Args:
            target_node: 目标节点ID
            edges: 该batch的边 [M, 6]，格式 (batch_idx, h, r, t, h_idx, t_idx)
            max_depth: 最大回溯深度

        Returns:
            path: 关系序列 [r1, r2, ..., rN]，从查询节点到目标节点
                 如果无法回溯则返回 None
        """
        path = []
        current_node = target_node

        edges_np = edges.cpu().numpy()

        for depth in range(max_depth):
            # 查找指向当前节点的边
            incoming = edges_np[edges_np[:, 3] == current_node]

            if len(incoming) == 0:
                return None

            # 选择第一条边（简化实现，实际可能有多条路径）
            edge = incoming[0]
            relation = edge[2]
            source = edge[1]

            path.append(relation)
            current_node = source

        # 反转路径（从查询节点到目标节点）
        return path[::-1]

    def _match_rules(self, path: List[int], rules: List[Rule]) -> float:
        """
        检查路径是否匹配规则，返回匹配分数

        Args:
            path: 路径关系序列 [r1, r2, ...]
            rules: 候选规则

        Returns:
            score: 匹配规则的加权分数
        """
        score = 0.0

        for i, rule in enumerate(rules):
            if self._path_matches_rule_body(path, rule.body):
                # 使用可学习的规则权重
                score += self.rule_weights[i].item()

        return score

    def _path_matches_rule_body(self, path: List[int], body: List[int]) -> bool:
        """
        检查路径是否匹配规则体

        Args:
            path: [r1, r2, ...]
            body: [r1', r2', ...]

        Returns:
            是否匹配
        """
        if len(path) != len(body):
            return False

        return all(p == b for p, b in zip(path, body))


# 便捷函数：从文件加载规则并初始化RuleScorer
def load_rule_scorer(rule_path: str, n_rel: int, device='cuda') -> RuleScorer:
    """
    从规则文件加载并创建 RuleScorer

    Usage:
        scorer = load_rule_scorer('./data/fb15k-237/rules.pkl', n_rel=237)
    """

    with open(rule_path, 'rb') as f:
        rules = pickle.load(f)
```

### 5.3 优化的规则评分（高效版本）

上述实现在每个节点都回溯路径，效率较低。下面是优化版本：

```python
class FastRuleScorer(nn.Module):
    """
    高效规则评分器：预计算路径表示

    核心优化：
    1. 在每层传播时记录路径历史
    2. 使用向量化匹配规则
    """
    def __init__(self, rules: List[Rule], n_rel: int, max_path_len=3, device='cuda'):
        super().__init__()
        self.rules = rules
        self.n_rel = n_rel
        self.max_path_len = max_path_len
        self.device = device

        # 规则权重
        self.rule_weights = nn.Parameter(
            torch.tensor([r.confidence for r in rules], dtype=torch.float32)
        )

        # 预计算规则的路径表示矩阵
        self.rule_patterns = self._build_rule_patterns()

    def _build_rule_patterns(self):
        """
        构建规则模式矩阵 [n_rules, max_path_len, n_rel]
        用于快速向量化匹配
        """
        n_rules = len(self.rules)
        patterns = torch.zeros(n_rules, self.max_path_len, self.n_rel)

        for i, rule in enumerate(self.rules):
            for j, rel in enumerate(rule.body):
                if j < self.max_path_len:
                    patterns[i, j, rel] = 1.0

        return patterns.to(self.device)

    def score_nodes_fast(self,
                        path_encodings: torch.Tensor,  # [N, max_path_len, n_rel]
                        query_rel: torch.Tensor,       # [N]
                        ) -> torch.Tensor:             # [N]
        """
        快速规则评分（向量化实现）

        Args:
            path_encodings: 节点的路径编码 [N, max_path_len, n_rel]
                          one-hot编码，path_encodings[i, j, k]=1 表示第j步关系是k
            query_rel: 每个节点对应的查询关系 [N]

        Returns:
            rule_scores: [N]
        """
        N = path_encodings.size(0)
        scores = torch.zeros(N, device=self.device)

        # 对每条规则，计算匹配度
        for i, rule in enumerate(self.rules):
            # 检查查询关系是否匹配规则头
            mask = (query_rel == rule.head)  # [N]

            if not mask.any():
                continue

            # 计算路径与规则体的匹配度
            # pattern: [max_path_len, n_rel]
            # paths: [N, max_path_len, n_rel]
            pattern = self.rule_patterns[i]  # [max_path_len, n_rel]

            # 逐位匹配
            match = (path_encodings * pattern).sum(dim=[1, 2])  # [N]
            full_match = (match == rule.length).float()  # 完全匹配

            # 累加规则权重
            scores += full_match * mask.float() * self.rule_weights[i]

        return scores
```

```python
class GNNModel(torch.nn.Module):
```

### 7.2 规则索引优化

**问题**：在线匹配规则效率低

**解决方案**：预计算规则触发表

```python
class PrecomputedRuleScorer(nn.Module):
    """
    预计算规则评分器

    离线预计算：path -> matching_rules
    在线查表：O(1)复杂度
    """
    def __init__(self, rules, kg_index, max_path_len=3):
        super().__init__()

        # 预计算路径->规则映射
        print("[PrecomputedRuleScorer] 预计算规则触发表...")
        self.path_rule_map = self._precompute_path_rules(rules, kg_index, max_path_len)

        self.rule_weights = nn.Parameter(
            torch.tensor([r.confidence for r in rules], dtype=torch.float32)
        )

    def _precompute_path_rules(self, rules, kg_index, max_path_len):
        """
        预计算所有可能路径触发的规则

        Returns:
            {
                (node_id, path_tuple): [rule_idx1, rule_idx2, ...],
                ...
            }
        """
        path_rule_map = defaultdict(list)

        # 遍历所有节点，枚举所有可能路径
        for node_id in kg_index.keys():
            for path_len in range(1, max_path_len + 1):
                # DFS 枚举路径
                paths = self._enumerate_paths(node_id, kg_index, path_len)

                for path in paths:
                    # 检查匹配的规则
                    for rule_idx, rule in enumerate(rules):
                        if self._path_matches(path, rule.body):
                            key = (node_id, tuple(path))
                            path_rule_map[key].append(rule_idx)

        return dict(path_rule_map)

    def _enumerate_paths(self, start_node, kg_index, length, current_path=[]):
        """DFS 枚举指定长度的路径"""
        if length == 0:
            return [current_path]

        paths = []
        for relation, neighbor in kg_index.get(start_node, []):
            extended_path = current_path + [relation]
            paths.extend(self._enumerate_paths(neighbor, kg_index, length - 1, extended_path))

        return paths

    def score_nodes(self, node_ids, paths):
        """
        O(1) 查表获取规则分数

        Args:
            node_ids: [N]
            paths: [N, path_len]

        Returns:
            scores: [N]
        """
        scores = torch.zeros(len(node_ids))

        for i, (node_id, path) in enumerate(zip(node_ids, paths)):
            key = (node_id, tuple(path.tolist()))
            if key in self.path_rule_map:
                rule_indices = self.path_rule_map[key]
                scores[i] = self.rule_weights[rule_indices].sum()

        return scores
```

### 7.3 规则蒸馏（最高效方案）

**核心思想**：将规则知识蒸馏到神经网络，避免在线规则匹配

```python
class RuleDistillation:
    """
    规则知识蒸馏

    流程：
    1. 使用规则评分器生成"教师信号"
    2. 训练神经网络拟合规则分数
    3. 推理时仅使用神经网络（无需规则匹配）
    """
    def __init__(self, rule_scorer, neural_scorer):
        self.rule_scorer = rule_scorer
        self.neural_scorer = neural_scorer

    def distill(self, train_loader, epochs=10):
        """
        蒸馏训练
        """
        optimizer = torch.optim.Adam(self.neural_scorer.parameters(), lr=0.001)

        for epoch in range(epochs):
            for batch in train_loader:
                nodes, edges, query_rel = batch

                # 教师：规则分数
                with torch.no_grad():
                    teacher_scores = self.rule_scorer.score_nodes(nodes, edges, query_rel)

                # 学生：神经网络分数
                student_scores = self.neural_scorer(nodes, edges, query_rel)

                # 蒸馏损失（MSE）
                loss = F.mse_loss(student_scores, teacher_scores)

                optimizer.zero_grad()
                loss.backward()
                optimizer.step()

            print(f"Epoch {epoch}, Distillation Loss: {loss.item():.4f}")
```

**使用方式**：

```python

    distiller = RuleDistillation(rule_scorer, neural_scorer)
    distiller.distill(train_loader)

# 推理阶段：仅使用神经网络（高效）

```

#### 1️⃣ AMIE/AMIE+ (推荐⭐⭐⭐⭐⭐)

**论文**:
- AMIE: "Association Rule Mining under Incomplete Evidence in Ontological Knowledge Bases" (WWW 2013)
- AMIE+: "Fast Rule Mining in Ontological Knowledge Bases with AMIE+" (VLDB 2015)

**核心思想**:
- 基于关联规则挖掘（Apriori 算法变体）
- 从单原子规则开始逐步扩展
- 使用 PCA（Partial Completeness Assumption）假设处理开放世界

**算法流程**:
```python
def AMIE_Plus(KG, min_support, min_confidence):
    """
    AMIE+ 核心算法
    """
    # 步骤1: 初始化候选规则队列
    # 1-hop 规则: r(X,Y) => r'(X,Y)
    queue = initialize_1hop_rules(KG)
    mined_rules = []

    # 步骤2: 迭代扩展规则
    while queue:
        rule = queue.pop()

        # 计算支持度和置信度
        sup = compute_support(rule, KG)
        conf = compute_pca_confidence(rule, KG)

        # 剪枝1: 支持度过低
        if sup < min_support:
            continue

        # 剪枝2: 置信度过低
        if conf < min_confidence:
            continue

        mined_rules.append(rule)

        # 步骤3: 扩展规则（添加新原子）
        for new_atom in generate_refinements(rule, KG):
            extended_rule = rule + new_atom

            # 剪枝3: 避免冗余规则
            if is_redundant(extended_rule, mined_rules):
                continue

            # 剪枝4: 避免过长规则
            if len(extended_rule.body) > max_length:
                continue

            queue.append(extended_rule)

    return mined_rules

def compute_pca_confidence(rule, KG):
    """
    PCA 置信度计算（考虑开放世界假设）

    标准置信度问题:
        conf(r) = support(r) / count(body(r))
        在KG不完整时会高估置信度

    PCA 置信度:
        pca_conf(r) = support(r) / (support(r) + count(body(r)) - support(head(r)))
    """
    sup = count_instantiations(rule.body + rule.head, KG)
    body_count = count_instantiations(rule.body, KG)
    head_count = count_instantiations(rule.head, KG)

    return sup / (sup + body_count - head_count)
```

**优势**:
- ✅ **完备性高**: 能保证挖掘所有满足阈值的规则
- ✅ **理论严谨**: 基于成熟的关联规则挖掘理论
- ✅ **可解释性强**: 挖掘的规则是显式的 Horn 子句
- ✅ **开源工具**: Java 实现，易于使用 (https://github.com/lajus/amie)

**劣势**:
- ⚠️ **计算开销大**: 时间复杂度 O(|R|³ × |E|)，大图上较慢
- ⚠️ **内存消耗高**: 需要存储所有中间候选规则
- ⚠️ **参数敏感**: `min_support` 和 `min_confidence` 需要仔细调优

**适用场景**:
- 中小规模数据集（<100K 三元组）
- 需要高质量、可解释规则
- 离线预处理（可以接受较长挖掘时间）

#### 2️⃣ AnyBURL (推荐⭐⭐⭐⭐⭐)

**论文**: "Anytime Bottom-Up Rule Learning for Knowledge Graph Completion" (IJCAI 2019)

**核心思想**:
- 随机游走采样路径
- Bottom-up 构建规则
- Anytime 算法（可随时停止，返回当前最佳规则）

**算法流程**:
```python
def AnyBURL(KG, time_budget):
    """
    AnyBURL 核心算法
    """
    rules = {}
    start_time = time.time()

    # 主循环：在时间预算内不断采样
    while time.time() - start_time < time_budget:
        # 步骤1: 随机采样一个三元组作为目标
        h, r, t = random.choice(KG)

        # 步骤2: 随机游走寻找路径
        # 从 h 出发，随机游走到 t
        path = random_walk(h, t, KG, max_steps=5)

        if path is None:
            continue

        # 步骤3: 提取路径规则
        # path = [r1, r2, r3], 目标关系 = r
        rule = Rule(body=path, head=r)

        # 步骤4: 更新规则统计
        if rule not in rules:
            rules[rule] = {'support': 0, 'body_count': 0}

        rules[rule]['support'] += 1

        # 步骤5: 统计规则体出现次数
        # （需要额外采样）
        if random.random() < 0.1:  # 10% 概率
            for h2, _, _ in KG:
                if path_exists(h2, path, KG):
                    rules[rule]['body_count'] += 1

    # 计算置信度并排序
    for rule in rules:
        conf = rules[rule]['support'] / max(1, rules[rule]['body_count'])
        rule.confidence = conf

    return sorted(rules, key=lambda r: r.confidence, reverse=True)

def random_walk(start, target, KG, max_steps):
    """
    从 start 随机游走到 target
    """
    path = []
    current = start

    for step in range(max_steps):
        if current == target:
            return path

        # 获取邻居
        neighbors = KG.get_neighbors(current)
        if not neighbors:
            return None

        # 随机选择一个邻居
        relation, next_node = random.choice(neighbors)
        path.append(relation)
        current = next_node

    return None if current != target else path
```

**优势**:
- ✅ **效率极高**: 线性时间复杂度 O(|E|)
- ✅ **可扩展性强**: 适用于超大规模图（百万级三元组）
- ✅ **Anytime 特性**: 可随时停止，获得当前最佳规则
- ✅ **实现简单**: 核心代码不到200行

**劣势**:
- ⚠️ **非确定性**: 随机采样，每次运行结果略有不同
- ⚠️ **覆盖不完全**: 可能遗漏低频但高质量的规则
- ⚠️ **置信度估计偏差**: 基于采样估计，不如 AMIE+ 精确

**适用场景**:
- 大规模数据集（>100K 三元组）
- 需要快速获得规则
- 对规则完备性要求不高

#### 3️⃣ Neural-LP (推荐⭐⭐⭐)

**论文**: "Differentiable Learning of Logical Rules for Knowledge Base Reasoning" (NeurIPS 2017)

**核心思想**:
- 将逻辑规则表示为神经网络
- 通过反向传播端到端学习规则
- 使用注意力机制学习软规则权重

**算法流程**:
```python
class NeuralLP(nn.Module):
    """
    Neural-LP 核心模型
    """
    def __init__(self, n_rel, n_ent, max_depth):
        super().__init__()
        self.n_rel = n_rel
        self.n_ent = n_ent
        self.max_depth = max_depth

        # 关系嵌入（用于注意力计算）
        self.rel_emb = nn.Embedding(n_rel, 128)

        # 注意力网络（学习规则权重）
        self.attn = nn.Sequential(
            nn.Linear(128 * 2, 64),
            nn.ReLU(),
            nn.Linear(64, 1),
            nn.Softmax(dim=1)
        )

    def forward(self, query_rel, query_ent, KG):
        """
        前向传播：软规则推理

        Args:
            query_rel: 查询关系
            query_ent: 查询实体
            KG: 知识图谱（邻接矩阵形式）

        Returns:
            scores: 每个实体的得分 [n_ent]
        """
        # 初始化：查询实体分数为1
        scores = torch.zeros(self.n_ent)
        scores[query_ent] = 1.0

        # 迭代推理（模拟多跳路径）
        for depth in range(self.max_depth):
            # 步骤1: 计算注意力权重（软规则选择）
            query_emb = self.rel_emb(query_rel)  # [128]

            attn_scores = []
            for r in range(self.n_rel):
                rel_emb = self.rel_emb(r)
                concat = torch.cat([query_emb, rel_emb])
                attn = self.attn(concat)
                attn_scores.append(attn)

            attn_weights = torch.stack(attn_scores)  # [n_rel, 1]

            # 步骤2: 软传播（加权路径聚合）
            new_scores = torch.zeros(self.n_ent)
            for r in range(self.n_rel):
                # KG[r] 是关系 r 的邻接矩阵 [n_ent, n_ent]
                propagated = torch.matmul(KG[r], scores)
                new_scores += attn_weights[r] * propagated

            scores = new_scores

        return scores

    def extract_rules(self, min_weight=0.1):
        """
        从训练好的模型提取显式规则

        Returns:
            rules: List[Rule]
        """
        rules = []

        # 遍历所有查询关系
        for query_rel in range(self.n_rel):
            query_emb = self.rel_emb(query_rel)

            # 提取高权重的路径模式
            for depth in range(1, self.max_depth + 1):
                # 枚举所有长度为 depth 的路径
                paths = self._enumerate_paths(depth)

                for path in paths:
                    # 计算路径权重
                    weight = 1.0
                    for rel in path:
                        rel_emb = self.rel_emb(rel)
                        concat = torch.cat([query_emb, rel_emb])
                        attn = self.attn(concat).item()
                        weight *= attn

                    # 过滤低权重路径
                    if weight > min_weight:
                        rule = Rule(
                            body=path,
                            head=query_rel,
                            confidence=weight,
                            support=-1  # 软规则无法直接统计支持度
                        )
                        rules.append(rule)

        return rules
```

**优势**:
- ✅ **端到端学习**: 规则学习与任务优化联合训练
- ✅ **软规则**: 可以学习模糊/概率性规则
- ✅ **灵活性高**: 易于集成到神经网络框架

**劣势**:
- ⚠️ **可解释性差**: 提取的规则不如符号挖掘清晰
- ⚠️ **训练开销大**: 需要端到端训练，耗时长
- ⚠️ **规则质量**: 提取的规则置信度估计不准确

**适用场景**:
- 需要将规则学习融入端到端训练
- 对可解释性要求不高
- 有充足的GPU资源

#### 4️⃣ DRUM (推荐⭐⭐⭐⭐)

**论文**: "DRUM: End-To-End Differentiable Rule Mining On Knowledge Graphs" (NeurIPS 2019)

**核心思想**:
- Neural-LP 的改进版
- 使用 RNN 编码路径
- 显式建模规则体和规则头的关系

**关键改进**:
```python
class DRUM(nn.Module):
    """
    DRUM 核心模型
    """
    def __init__(self, n_rel, n_ent, emb_dim=128, max_depth=3):
        super().__init__()
        self.n_rel = n_rel
        self.n_ent = n_ent
        self.max_depth = max_depth

        # 关系嵌入
        self.rel_emb = nn.Embedding(n_rel, emb_dim)

        # RNN 编码路径
        self.path_encoder = nn.GRU(emb_dim, emb_dim, batch_first=True)

        # 规则评分网络
        self.rule_scorer = nn.Sequential(
            nn.Linear(emb_dim * 2, 64),
            nn.ReLU(),
            nn.Linear(64, 1)
        )

    def forward(self, query_rel, query_ent, KG):
        """
        前向传播：基于 RNN 的软规则推理
        """
        scores = torch.zeros(self.n_ent)
        scores[query_ent] = 1.0

        query_emb = self.rel_emb(query_rel)

        # 存储所有路径及其编码
        paths = {(): scores}  # (path_tuple): entity_scores

        for depth in range(1, self.max_depth + 1):
            new_paths = {}

            for path, path_scores in paths.items():
                # 尝试扩展路径（添加一个新关系）
                for r in range(self.n_rel):
                    # 编码当前路径
                    path_seq = torch.tensor(list(path) + [r])
                    path_embs = self.rel_emb(path_seq).unsqueeze(0)
                    _, path_enc = self.path_encoder(path_embs)
                    path_enc = path_enc.squeeze(0)

                    # 计算路径与查询关系的匹配度
                    concat = torch.cat([path_enc, query_emb])
                    rule_score = torch.sigmoid(self.rule_scorer(concat))

                    # 传播分数
                    propagated = torch.matmul(KG[r], path_scores)
                    weighted_propagated = rule_score * propagated

                    # 记录新路径
                    new_path = path + (r,)
                    if new_path not in new_paths:
                        new_paths[new_path] = weighted_propagated
                    else:
                        new_paths[new_path] += weighted_propagated

            paths.update(new_paths)

        # 聚合所有路径的分数
        final_scores = torch.zeros(self.n_ent)
        for path_scores in paths.values():
            final_scores += path_scores

        return final_scores
```

**优势**:
- ✅ **改进的路径编码**: RNN 编码比简单注意力更强
- ✅ **更好的规则提取**: 可以提取更清晰的规则
- ✅ **性能提升**: 在多个数据集上优于 Neural-LP

**劣势**:
- ⚠️ **计算开销**: RNN 编码增加了计算成本
- ⚠️ **仍需端到端训练**: 不如符号挖掘快速

#### 5️⃣ RLvLR (推荐⭐⭐⭐⭐)

**论文**: "Reinforcement Learning based Path Exploration for Sequential Explainable Recommendation" (TKDE 2022)

**核心思想**:
- 使用强化学习搜索规则
- 将规则挖掘建模为序列决策问题
- 奖励函数设计为规则质量度量

**算法流程**:
```python
class RLvLR:
    """
    基于强化学习的规则挖掘
    """
    def __init__(self, KG, n_rel, state_dim=128):
        self.KG = KG
        self.n_rel = n_rel

        # 策略网络（Actor）
        self.policy = nn.Sequential(
            nn.Linear(state_dim, 64),
            nn.ReLU(),
            nn.Linear(64, n_rel),
            nn.Softmax(dim=-1)
        )

        # 价值网络（Critic）
        self.value = nn.Sequential(
            nn.Linear(state_dim, 64),
            nn.ReLU(),
            nn.Linear(64, 1)
        )

    def mine_rules(self, n_episodes=1000):
        """
        强化学习挖掘规则
        """
        rules = []

        for episode in range(n_episodes):
            # 随机选择一个起始三元组
            h, target_r, t = random.choice(self.KG)

            # 状态：当前路径编码
            state = self.encode_state([])
            current_node = h
            path = []

            # 步骤1: 策略网络生成路径
            for step in range(max_steps):
                # 选择下一个关系
                action_probs = self.policy(state)
                action = torch.multinomial(action_probs, 1).item()

                # 执行动作（沿着关系移动）
                next_nodes = self.KG.get_neighbors(current_node, action)

                if not next_nodes:
                    break

                next_node = random.choice(next_nodes)
                path.append(action)

                # 更新状态
                state = self.encode_state(path)
                current_node = next_node

                # 到达目标节点
                if current_node == t:
                    # 创建规则
                    rule = Rule(body=path, head=target_r)

                    # 计算奖励（规则质量）
                    reward = self.compute_reward(rule, self.KG)

                    # 更新策略（Policy Gradient）
                    self.update_policy(state, action, reward)

                    if reward > threshold:
                        rules.append(rule)

                    break

        return rules

    def compute_reward(self, rule, KG):
        """
        计算规则质量作为奖励
        """
        # 计算置信度
        conf = compute_confidence(rule, KG)

        # 计算覆盖度（多样性）
        coverage = compute_coverage(rule, KG)

        # 规则长度惩罚（鼓励简短规则）
        length_penalty = 1.0 / (1.0 + len(rule.body))

        # 综合奖励
        reward = conf * coverage * length_penalty

        return reward
```

**优势**:
- ✅ **搜索效率高**: RL 引导搜索，避免盲目枚举
- ✅ **质量导向**: 奖励函数可灵活设计，优化目标明确
- ✅ **可扩展**: 适用于大规模图

**劣势**:
- ⚠️ **训练复杂**: RL 训练不稳定，需要调参
- ⚠️ **实现难度高**: 相比符号挖掘实现更复杂

### C.3 算法选择建议

#### 推荐方案（按数据集规模）

**小规模数据集** (< 50K 三元组):
```
推荐: AMIE+
理由:
- 完备性高，能挖掘所有高质量规则
- 计算开销可接受
- 规则质量最高

命令:
java -jar amie-plus.jar -datapath train.txt -mins 5 -minc 0.1
```

**中等规模数据集** (50K - 200K 三元组):
```
推荐: AnyBURL
理由:
- 平衡速度与质量
- Anytime 特性，可随时停止
- 规则数量充足

命令:
java -jar AnyBURL.jar -train train.txt -seconds 1800
```

**大规模数据集** (> 200K 三元组):
```
推荐: AnyBURL + 后处理过滤
理由:
- 唯一能在合理时间内完成的方法
- 配合统计过滤提升质量

命令:
java -jar AnyBURL.jar -train train.txt -seconds 3600
python filter_low_quality_rules.py
```
